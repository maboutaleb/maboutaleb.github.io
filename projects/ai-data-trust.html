AI Data Trust Platform

A microservices architecture sketch for a platform-level trust layer: sync a real data catalog, profile tables on a schedule, score and explain trust per table with an LLM, and surface it all on a dashboard with historical trend lines — the shape of a scaled-up semantic layer, not a finished product.

OpenMetadata Apache Airflow Docker Compose Next.js Postgres

Honest status

This project is included deliberately as an architecture and roadmap piece, not a working demo. It's early — services are scaffolded, the orchestration is defined in docker-compose, but it hasn't been run end-to-end as a live system yet. It's here because the design decisions it captures are directly relevant to this role's "prototyping and iteration on integrated data catalog and data fabric capabilities" responsibility, even before the implementation is finished.

The idea

dap_monitor proved a trust-scoring methodology for one specific reconciliation problem (three revenue sources). This project asks: what would it look like to run that same idea — a governed, explainable trust score per table — as a standing platform service instead of a one-off script, wired into a real metadata catalog (OpenMetadata) instead of a bespoke CSV pipeline?

Planned service architecture

  • catalog-sync — syncs table/column metadata into and out of OpenMetadata, so trust scores and lineage live next to the same catalog other tools already read from, instead of a second, disconnected source of truth.
  • profiler — scheduled Airflow DAGs that profile tables (freshness, volume, null rates, distribution drift) on a recurring cadence rather than on-demand.
  • trust-scorer — computes a per-table trust score from profiling output, generalizing the weighted-component approach (completeness, alignment, stability) proven in dap_monitor beyond a single metric.
  • ai-expectations — uses an LLM to draft candidate data-quality expectations/rules for a table from its observed profile, instead of requiring every rule to be hand-authored.
  • explanations — generates plain-language explanations for why a table's trust score changed, so a score isn't just a number without a story.
  • dashboard — a Next.js app showing per-table trust scores with color-coded badges (🟢/🟡/🔴) and historical sparkline trends, drilling into a per-table detail view.
Orchestration: docker-compose wires up Postgres, OpenMetadata, and Airflow as the platform substrate, with each trust/AI service as its own container — service boundaries chosen so profiling, scoring, and explanation can evolve independently.

What the dashboard is meant to show

The homepage renders a card per table with a score badge and a compact SVG sparkline of the score's recent history — the intent is that a governance reviewer can scan dozens of tables at a glance and immediately see which ones are trending down, not just which ones are currently red. Each card links to a per-table detail page for the full history and drivers.

Why include an unfinished project

Because the role isn't just "operate an existing semantic layer" — it's also "research emerging semantic layer, metadata, and AI-enablement tooling and surface findings... for evaluation," and "support prototyping and iteration on integrated data catalog and data fabric capabilities." This project is evidence of that muscle: evaluating where an off-the-shelf catalog (OpenMetadata) ends and where custom trust/AI logic needs to begin, and sketching the service boundaries before writing production code.
